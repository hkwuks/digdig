# 修复会话迁移锁
> Task version: v3
> Status: completed

## Goal
避免已迁移会话受旧目录锁影响，避免首次迁移时错误删除其他进程的锁。

## Task Kind
- Kind: defect

## Requirements
- 已完成迁移的数据库由 SQLite 控制并发，打开时不需要旧目录锁。
- 首次迁移保持旧目录锁与 SQLite 事务保护；不能根据时间戳自动删除锁。
- 记录无法安全自动恢复的遗留锁和旧版本进程局限。

## Acceptance Criteria
- 已迁移会话在旧目录锁存在时可正常打开。
- 未迁移会话遇到任意已有锁时返回 SESSION_BUSY，不删除锁或创建数据库。
- 并发首次迁移和 SQLite 事务测试通过；已有会话数据不变。

## In Scope
会话锁、数据库打开路径、必要测试。

## Out of Scope
旧版本程序的锁算法和 SearXNG 分页。

## Risks / Deferred Items
崩溃遗留锁需确认无进程持有后手动清除；旧版本进程自身仍可能按超时删除持有中的锁。

## v2：崩溃恢复
- 对新协议创建的锁使用 SQLite 进程级互斥；只有持有恢复互斥且锁标记完整可识别时才恢复，避免依赖 PID 和超时。
- 老锁、缺失或损坏标记保持 SESSION_BUSY，提示确认无进程使用后人工清理；创建目录与写入标记间崩溃同样无法自动识别。
- 旧版本程序不可与新版本并发访问同一会话；不引入旧程序兼容代码。
- 测试真实进程崩溃、活锁持有、多个恢复者及不可信锁；验证 Windows，Linux 在 CI 验证。

## v3：迁移提示
- 文档说明先停止旧版，再迁移，迁移后所有进程使用 SQLite 版。
- 未识别锁报错说明停止所有使用该会话的 dg 进程、确认后清理具体 `.lock` 路径；不得删除 SQLite 数据库。
- 保持现有锁协议与错误代码，不新增清理命令。
